## 1.2 Убрать автоматическое добавление контента в БД (Priority 2)
Данная фишка имела вес в начале проекта, где скорость создание паука была на 1 месте, было решено что лучше вынести автоматическое добавление контента в Middleware, что-бы не нарушать [__Принцип единственной ответственности__](https://en.wikipedia.org/wiki/Single-responsibility_principle)

## 1.3 Middleware сортировка по важности (Priority 2)
Было решено что Middleware работает очень странно, что недопустимо если Middlewar-ов будет 3-5 или 10, поэтому я предлагаю идею того что Middleware будет сам указывать свою важность.
```python
# Пример Middleware:

class Middleware(SpiderMiddleware):
    PRIORITY: Literal["first", "end"] | float = "end"
```
Если Middleware имеет приоритет first, то он попытается выполниться первым, но если в очереди будет ещё Middleware с приоритетом first, то он должен уступить место:
```text
                    ┌─────────────────────────────────────┐
                    │         Входящий запрос             │
                    └──────────────────┬──────────────────┘
                                       │
                                       ▼
                    ┌─────────────────────────────────────┐
                    │   Сбор всех Middleware + PRIORITY   │
                    │                                     │
                    │  MW-A : PRIORITY = "first"          │
                    │  MW-B : PRIORITY = -50.0            │
                    │  MW-C : PRIORITY = "first"  ← конфликт
                    │  MW-D : PRIORITY = 0.0              │
                    │  MW-E : PRIORITY = "end"            │
                    │  MW-F : PRIORITY = "end"    ← конфликт
                    └──────────────────┬──────────────────┘
                                       │
                                       ▼
                    ┌─────────────────────────────────────┐
                    │      Сортировка по PRIORITY         │
                    │                                     │
                    │  Правило: "first" < float < "end"   │
                    │                                     │
                    │  Конфликт "first" → уступи место    │
                    │  (FIFO / по имени класса)           │
                    │                                     │
                    │  Конфликт "end"   → уступи место    │
                    │  (FIFO / по имени класса)           │
                    └──────────────────┬──────────────────┘
                                       │
                                       ▼
   ┌───────────────────────────────────────────────────────────┐
   │                    Очередь выполнения                     │
   │                                                           │
   │   1. MW-A  (first)   ─┐                                   │
   │   2. MW-C  (first)   ─┘ ← один уступает другому           │
   │                                                           │
   │   3. MW-B  (-50.0)                                        │
   │   4. MW-D  (0.0)                                          │
   │                                                           │
   │   5. MW-E  (end)     ─┐                                   │
   │   6. MW-F  (end)     ─┘ ← один уступает другому           │
   └───────────────────────────┬───────────────────────────────┘
                               │
                               ▼
              ┌────────────────────────────────┐
              │   Последовательное выполнение  │
              │                                │
              │   MW-A → MW-C → MW-B → MW-D    │
              │        → MW-E → MW-F           │
              └────────────────┬───────────────┘
                               │
                               ▼
                    ┌─────────────────────┐
                    │   Целевой обработчик│
                    └─────────────────────┘
```

# Планы на будущее V2.0

## 2.1 Полное перестройка spider-manager (Priority 1)
На данный момент менеджер пауков, и перенос их на Celery, самая костыльная часть, хотя и является основным замыслом проекта, поэтому в версии 2.0 я хочу полностью переработать систему, перенести память на на JSON а на Redis, добавить возможность пачками переносить пауков, что-бы в 1 Celery воркере было 3-5 пауков (выбирается конфигурацией)

## 2.2 Пересмотр API (Priority 2)
На данный момент данный проект любит когда каждая таблица имеет отдельный API Endpoint, например путь к API с книгами `/api/v1/books/read` - предлагается изменить данный подход, на `RPC`:
```json
// GET /api/v2/content
{
    "table": "book",
    "method": "read"
}
```
Библиотека которая нам поможет [fastapi-jsonrpc](https://github.com/smagafurov/fastapi-jsonrpc)
